# Алиса через Яндекс Диск — версия 0.2.0

Подготовлен новый канал связи. Установка на дачный роутер и проверка на Билайне
при ограничениях ещё НЕ выполнены. Доступность приложения Диска не доказывает
доступность `webdav.yandex.ru` и достаточную скорость ответа Алисе.

## Скачать заранее

- [ZIP для облачной функции](https://github.com/ppmonch2/zbt-we1626-openwrt/raw/refs/heads/main/downloads/Ballu-Alice-Function-0.2.0.zip).
- [ZIP для роутера](https://github.com/ppmonch2/zbt-we1626-openwrt/raw/refs/heads/main/downloads/Ballu-Alice-Router-0.2.0.zip).

Это два разных архива. Первый загружается целиком в Yandex Cloud. Второй
распаковывается для установки на роутер. В архивах нет ваших паролей и ключей.

## Что уже можно подготовить из дома

1. Скачайте оба ZIP и сохраните эту инструкцию офлайн.
2. Для Диска нужен аккаунт с доступом WebDAV. По текущей документации Яндекса
   доступ зависит от тарифа Яндекс 360. Само наличие обычного Диска недостаточно.
   Не покупайте VPS: этот вариант его не использует.
3. В Яндекс ID откройте «Безопасность» → «Пароли приложений» → создание пароля
   для **«Файлы WebDAV»**. Если такого доступа нет, сначала проверьте условия
   тарифа. Используйте отдельный пароль приложения, не основной пароль аккаунта.
4. Сохраните логин и пароль у себя. При переносе пароля уберите разделительные
   пробелы. В переписку и на GitHub пароль присылать не нужно. Можно использовать
   отдельный аккаунт Диска для отопления: пароль WebDAV имеет доступ к файлам
   аккаунта, а не только к папке отопления.
5. Облачный ZIP можно установить заранее по следующему разделу, но
   **`HEATBRIDGE_TRANSPORT` пока оставьте `cloud`**. До установки программы
   на роутер переходить на `disk` не нужно.

## Обновить облачную функцию

1. Откройте **Yandex Cloud → каталог ballu-heatbridge → Cloud Functions**.
2. Откройте ту функцию, которая подключена к навыку «Дачное отопление».
   В присланных логах её ID: `d4e0060i5ufrhuj73t9u`, название — `ballu-alice`.
   Новую функцию и новый навык создавать не нужно.
3. Откройте **«Редактор»**. Выберите загрузку кода ZIP-архивом и загрузите
   **Ballu-Alice-Function-0.2.0.zip целиком**, не распаковывая его.
4. Оставьте Python 3.12, точку входа `skill.handler`, память 128 МБ,
   тайм-аут 3 секунды, прежний сервисный аккаунт и существующие переменные.
5. Добавьте переменные:

| Имя поля | Что вписать |
|---|---|
| `HEATBRIDGE_TRANSPORT` | Пока `cloud`. После проверки и запуска роутера — `disk` |
| `HEATBRIDGE_DISK_LOGIN` | Логин аккаунта, на котором находится Диск |
| `HEATBRIDGE_DISK_APP_PASSWORD` | Созданный пароль приложения WebDAV без пробелов |
| `HEATBRIDGE_DISK_FOLDER` | `heatbridge-v1` |

Существующие `HEATBRIDGE_OWNER_LOGIN` / `HEATBRIDGE_OWNER_UID` и
`HEATBRIDGE_DEVICES_JSON` оставьте прежними. Они отвечают за владельца навыка
и ваши h1–h4. Логин Диска может отличаться от владельца навыка.
Старые переменные AWS и очереди сохраняем для возврата к прежнему каналу;
в режиме `disk` программа их не использует.

6. Нажмите сохранение/создание версии и дождитесь окончания.
7. Откройте **«Тестирование»**, выберите тег `$latest`, шаблон «Без шаблона».
   В «Входные данные» вставьте:

```json
{"heatbridge_diagnostic":"version"}
```

8. Нажмите **«Запустить тест»**. В ответе должны быть `version: "0.2.0"`
   и пока `transport: "cloud"`. Этот тест не меняет температуру.

## На даче: установить программу на роутер

Ниже вариант с компьютером Windows для копирования и с вашим знакомым
приложением SSH для команд. Роутер и его флешка уже настроены: повторно
Entware устанавливать, форматировать флешку или прошивать роутер не нужно.

1. **Оставьте рабочую флешку в роутере.** Подключите компьютер и телефон к
   Wi-Fi роутера с флешкой — сети, где открывается `192.168.1.1:8765`.
2. На компьютере откройте папку «Загрузки». Нажмите правой кнопкой на
   **Ballu-Alice-Router-0.2.0.zip → «Извлечь всё»**.
3. В распакованном архиве найдите папку **`heatbridge-alice`**. Внутри должны
   быть `install.sh`, `SHA256SUMS`, программы и папка `www`.
4. Откройте Проводник Windows. В строку адреса вверху вставьте
   **`\\192.168.1.1`** и нажмите Enter. Откройте сетевую папку рабочей флешки,
   которую использовали при прежней установке. Имя этой папки зависит от
   настроек роутера. В её корне обычно видны `bin`, `etc`, `share`.
5. Скопируйте туда папку **`heatbridge-alice` целиком**. Должно получиться
   `heatbridge-alice/install.sh`, без дополнительной вложенной папки с именем ZIP.
   Если сетевой доступ не открывается, остановитесь на этом шаге: сначала
   нужен способ копирования на рабочую флешку. Не вынимайте её ради Windows
   и не соглашайтесь на предложение отформатировать EXT4.
6. На телефоне откройте знакомое SSH-приложение → подключение **endware**.
   Дождитесь строки `~ #`. Выполните:

```sh
ls /opt/heatbridge-alice/install.sh
```

7. Если показан путь `/opt/heatbridge-alice/install.sh`, выполните:

```sh
/opt/bin/sh /opt/heatbridge-alice/install.sh
```

Если написано `No such file or directory`, вернитесь к расположению папки
в шагах 3–5. Другие пути наугад вводить не нужно.

8. Дождитесь **`Files installed. Agent was NOT started.`**. Проверка контрольных
   сумм должна пройти без ошибок. Установка остановит прежний агент, добавит
   страницу Диска и обновит оболочку управления. Она сохраняет привязки
   обогревателей, их токены, пароль локального сайта и прежнюю конфигурацию очереди.
   Нативный клиент Ballu и прошивка роутера не заменяются.

## На даче: настроить через кнопки

1. В браузере телефона откройте **http://192.168.1.1:8765/disk.html**.
   Войдите с прежними логином и паролем локального интерфейса.
   На главной странице также появится ссылка **«Настроить связь Алисы через
   Яндекс Диск»**. Если видите старую страницу, обновите её.
2. В разделе **«1. Подключить Диск»** заполните:
   - «Логин Яндекса» — тот же аккаунт Диска, что в облачной функции;
   - «Пароль приложения» — пароль WebDAV без пробелов;
   - «Папка обмена» — **`heatbridge-v1`**.
3. Нажмите **«Сохранить настройки»**. Должно появиться сообщение, что настройки
   сохранены. Поле пароля очистится — это нормально, сервер не возвращает пароль.
4. Нажмите **«Проверить запись и чтение»**, подождите до 30 секунд.
   Программа создаст служебные папки, запишет тестовый файл, прочитает и удалит его.
   Обогреватели при этом не получают команд.
5. Нужен результат **«Успешно: файл записан, прочитан и удалён»**.
   Если получена ошибка — сделайте снимок сообщения и не переходите к запуску.
6. Нажмите **«Запустить через Диск»**, затем **«Обновить статус»**.
   Нужны сообщения «Канал: Яндекс Диск», «Программа запущена», затем
   «Диск отвечает, ожидаем команды». Этот статус ещё не означает выполнение
   команды обогревателем.
7. В облачной функции измените **`HEATBRIDGE_TRANSPORT` с `cloud` на `disk`**
   и сохраните новую версию. Теперь обе стороны используют один канал.

Если откладываете настройку Диска после установки, запустите прежний канал
кнопкой «Включить прежнюю очередь»; облачная функция при этом должна оставаться
в режиме `cloud`.

## Проверить результат из облака и Алисы

В Cloud Functions → ваша функция → «Тестирование», `$latest`, «Без шаблона»:

```json
{"heatbridge_diagnostic":"disk_probe"}
```

Нужен `status: "OK"`, `write_read_delete: true`. Это **проверка облако ↔ Диск**;
сама по себе она не проверяет доступ с роутера. Папки уже должны быть созданы
локальной кнопкой проверки. Команд обогревателям этот тест не отправляет.

Через 30–60 секунд после запуска роутера выполните второй тест:

```json
{"heatbridge_diagnostic":"disk_status"}
```

Он читает опубликованные роутером показания. Для каждого h1–h4 будут отдельно
уставка (`capabilities`, `temperature`) и измеренная температура (`properties`,
`temperature`). `NO_ROUTER_STATE` означает, что файл показаний ещё не появился.
`DEVICE_UNREACHABLE` у конкретного прибора означает отсутствие свежих достоверных
показаний, а не обязательно отключение его питания. Тест не меняет температуру.

В «Доме с Алисой» обновите список устройств подключения **«Дачное отопление»**,
чтобы появились свойства измеренной температуры. Проверьте одну команду одному
прибору, затем сценарий для четырёх. Находясь рядом, сравните уставку на дисплее
Ballu с заданной. Установка температуры сама по себе не включает выключенный прибор.

Главная проверка — повторить чтение показаний и команду **во время реальных
ограничений мобильного интернета**. Запишите время и сохраните сообщение Алисы.
Если уставка меняется, но Алиса выдаёт ошибку, доставка работает, а подтверждение
может не укладываться в её срок. Это ещё не завершённое испытание канала.

## Возврат к прежней очереди

1. В облачной функции установите `HEATBRIDGE_TRANSPORT=cloud` и сохраните версию.
2. На локальной странице Диска раскройте «Вернуться к прежнему каналу» и нажмите
   **«Включить прежнюю очередь»**. Сохранённый `alice.json` будет использован снова.
3. Локальные кнопки управления обогревателями доступны независимо от выбора канала.

## Что делает программа и что пока не проверено

- Один запрос Алисы передаётся одним файлом. Разные обогреватели обрабатываются
  параллельно; действия одному прибору выполняются по порядку. Для каждого
  действия требуется собственное шифрованное подтверждение Ballu.
- Команды действуют меньше трёх секунд. Просроченные не выполняются после
  восстановления связи. Обработанные ID сохраняются на USB, повторная доставка
  не запускает тот же запрос снова. После сбоя записи подтверждения оно может
  быть опубликовано повторно без повторного управления прибором.
- Роутер опрашивает папку примерно раз в секунду плюс время запроса. Это до
  86 400 запросов списка в сутки, плюс передача показаний и команд. Ограничения
  частоты WebDAV и пригодность постоянного опроса требуют проверки; бесплатная
  или неограниченная работа не обещается.
- Показания читаются по очереди через тот же локальный механизм, что кнопка
  «Проверить состояние». Это периодическое обновление, не непрерывная передача.
  Показания старше 90 секунд не выдаются за текущие.
- Уникальные файлы команд не перезаписывают друг друга. Подтверждения старше
  суток удаляются периодически, обработанные ID хранятся минимум двое суток.
- Пароль хранится в `/opt/etc/heatbridge/disk.json` с правами 0600. Он не попадает
  в ответы интерфейса и аргументы curl. На Диск не отправляются токены Ballu.
  Используется HTTPS с проверкой сертификата; перенаправления не выполняются.
- Алиса получает `DONE` только после реального подтверждения в пределах срока.
  Запись файла на Диск не считается успешным выполнением обогревателем.
- Проверены автоматическими тестами обмен с имитатором WebDAV, четыре прибора,
  дубликаты, просроченные команды, раздельные температуры, ошибки доступа,
  сохранение настроек, запуск/остановка и защита локальных POST-запросов.
  Настоящий WebDAV, конкретный роутер, потребление памяти и сеть Билайна ещё
  требуют испытания. Тесты не являются доказательством работы через белый список.
