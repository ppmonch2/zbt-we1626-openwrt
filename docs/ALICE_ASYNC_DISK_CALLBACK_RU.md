# Асинхронное управление Ballu через Алису и Яндекс Диск

## Причина ошибки
У Яндекса лимит ответа на действие 3 секунды. Очередь WebDAV, опрос роутера, физическое исполнение и обратное подтверждение часто дольше лимита. Поэтому прежний код выдавал ошибку при фактически выполненной команде.
Яндекс допускает асинхронный ответ на принятие команды, но ОБЯЗАТЕЛЬНО требует последующее уведомление о фактическом состоянии через /callback/state. Источник: https://yandex.ru/dev/dialogs/smart-home/doc/ru/reference/post-action

## Принцип
При HEATBRIDGE_ASYNC_ACTIONS=1 основная функция отвечает DONE только после успешной записи файла команд в WebDAV. DONE означает подтверждение постановки команды в очередь, а не выполнение нагревателем.
Отдельная облачная функция notify.handler по таймеру читает только подтвержденные реальные показания /acks/state-v1.json и посылает изменения через /callback/state. Дедупликация хранится в приватном файле /probes/alice-notify-ledger.json.
Все неуспешные операции записи остаются ошибками. Привязки Ballu и файлы роутера не изменяются.

## Подготовка
Нужен ZIP Ballu-Alice-Function.zip из последней успешной сборки Ballu-Alice-Cloud-Only в GitHub Actions, один и тот же архив для двух функций.
Нужны ID навыка Дачное отопление (Яндекс Диалоги, Общие сведения) и OAuth-токен владельца навыка для API уведомлений (не WebDAV-пароль). Навык необходимо хотя бы раз приватно опубликовать.
Токен хранить только в переменных Yandex Cloud. В чат токены и пароли не пересылать.
Документы: https://yandex.ru/dev/dialogs/smart-home/doc/ru/reference-alerts/resources-alerts

## Шаг 1: создать ballu-alice-notify
В Cloud Functions создать отдельную НЕПУБЛИЧНУЮ функцию ballu-alice-notify, Python 3.12, handler notify.handler, тайм-аут 15 секунд, ZIP Ballu-Alice-Function.zip.
Скопировать настройки из основной функции: HEATBRIDGE_TRANSPORT=disk, HEATBRIDGE_DISK_LOGIN, HEATBRIDGE_DISK_APP_PASSWORD, HEATBRIDGE_DISK_FOLDER=heatbridge-v1, HEATBRIDGE_DEVICES_JSON, HEATBRIDGE_OWNER_LOGIN либо HEATBRIDGE_OWNER_UID.
Добавить HEATBRIDGE_DIALOGS_SKILL_ID (идентификатор навыка) и HEATBRIDGE_DIALOGS_OAUTH_TOKEN (токен владельца навыка).
Проверить через вкладку Тестирование. Ожидается status=OK или status=UNCHANGED. При CALLBACK_REJECTED проверить HTTP-статус; не включать асинхронное управление до исправления ошибки.
Пробный вызов функции отправляет только реальные показания в Алису, не управляет обогревателями.

## Шаг 2: таймер
В Cloud Functions -> Триггеры -> Создать триггер -> Таймер -> Каждую минуту (cron: * * ? * * *). Цель — ballu-alice-notify, тег $latest. Сервисному аккаунту дать functions.functionInvoker. Публичный вызов функции не нужен.
Инструкция: https://yandex.cloud/ru/docs/functions/operations/trigger/timer-create

## Шаг 3: основная ballu-alice
Обновить основную функцию тем же ZIP и сохранить ВСЕ существующие переменные.
Добавить HEATBRIDGE_DIALOGS_SKILL_ID и HEATBRIDGE_DIALOGS_OAUTH_TOKEN.
Только после успешного теста callback и запуска таймера включить HEATBRIDGE_ASYNC_ACTIONS=1.
Если переключатель отсутствует, прежний безопасный синхронный механизм не меняется.

## Проверка
Из Алисы изменить уставку одного Ballu на 1 градус и проверить физически через локальную страницу роутера. После ближайшего запуска таймера должно обновиться фактическое состояние в Алисе.
Успешная постановка команды в очередь не гарантирует фактического исполнения: при сбое роутера или истечении срока команды состояние не изменится. При недоступном WebDAV функция должна вернуть ошибку, а не ложный успех. Таймер обновляет состояния не мгновенно, а примерно раз в минуту.
