# Незавершённая доработка прямого управления Ballu

Состояние на 15 ноября 2026 года. Пользователь уехал с дачи: доступен контроль
через Алису и консоль облака, но недоступны SSH роутера и установка его обновлений.
Обновление по сообщениям очереди не реализовано; очередь принимает только
проверенные команды обогревателям, а не команды оболочки или установку программ.

## Подтверждённые результаты

- Все четыре обогревателя локально управляются и имеют verified=true.
- h1: Холл_Окно; h2: Мансарда; h3: Холл_Лестница; h4: Кухня.
- Навык обнаруживает все четыре устройства.
- Ключи и права облачных сервисов работают; подтверждение команды читается
  облачной функцией и проходит проверку (read_ack: valid_confirmation=true).
- При изменении уставки прибор выполняет команду, но функция может вернуть
  DEVICE_UNREACHABLE по истечении своего ожидания. Это подтверждено журналом
  опубликованного навыка, а не только сообщением мобильного приложения.
- Последний замер: получение 1794726982.508246; подтверждение прибора
  1794726983.9942; завершение загрузки 1794726984.767169;
  expires_at=1794726984.7983398. Загрузка заняла 0.600195 секунды.
- Роутер 0.1.2 отправляет подтверждение перед удалением сообщения из очереди.
- Облако 0.1.7 повторно использует HTTPS-соединения и ждёт до 2.65 секунды;
  это пока не устранило ошибку. Нельзя объявлять настройку законченной.

## Подготовленная оптимизация, пока не установлена

В heatbridge-alice-worker разбор, проверка и формирование JSON объединены:
для успешной команды остаются три запуска jq вместо десяти. Проверка срока
непосредственно перед выполнением, проверка verified, атомарное создание записи
команды и проверка реального подтверждения прибора сохранены. 33 существующих
теста проходят. Выигрыш времени и расход памяти на реальном MIPS ещё не измерены.

## Что требуется для завершения

Обновление: облачная часть 0.1.9 и агент 0.1.3 теперь реализуют пункт 1 через
фоновое чтение существующим клиентом и закрытый снимок состояния. См.
[инструкцию выпуска](ALICE_STATE_0.1.9_RU.md). Обе части подготовлены, установка
на оборудовании владельца и фактическое отображение в приложении ещё не проверены.
В этом выпуске включена ранее подготовленная оптимизация worker (три запуска jq).

1. Показ текущей уставки: организовать свежие снимки состояния каждого прибора,
   передавать их в закрытое облачное хранилище, реализовать query и только после
   этого включать retrievable. Устаревшие данные не выдавать за актуальные.
   Сейчас retrievable=false, показ уставки действительно не реализован.
   Текущую измеренную температуру отличать от выставленной уставки.
2. Группы: снять последовательную блокировку всех приборов, организовать
   ограниченную параллельную обработку разных устройств и отдельную блокировку
   команд одному прибору. Сохранить защиту от повторной доставки и устаревших
   команд. Учесть память роутера 64 МБ, примерно 31 МБ свободно с учётом кеша.
   Фоновый опрос состояния не должен блокировать команды.
3. Проверить весь путь в пределах трёх секунд Алисы, в том числе реальное чтение
   подтверждения облаком. Получение задания очередью не считается выполнением.
4. Проверить одиночные команды, группу из четырёх приборов, независимые сбои,
   отсутствие одного прибора, обрыв интернета, повторную доставку, перезагрузку
   роутера и автоматический запуск после подключения USB.

Для установки роутерной части потребуется доступ к роутеру на месте либо
отдельный уже настроенный защищённый удалённый доступ. Пока его нет, не просить
пользователя выполнять SSH-команды и не обещать полностью облачное исправление.
Старые настройки и рабочие ключи сохранять. Не публиковать секреты в репозитории.
