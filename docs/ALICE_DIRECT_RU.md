# Прямое управление Алисой без облака HOMMYN

Цель: команды из Москвы должны доходить до Ballu при недоступном HOMMYN,
если с дачного роутера доступны выбранные сервисы Яндекса.

## Подтверждено на оборудовании

- Entware установлен на USB EXT4, веб-приложение запущено на Keenetic/NDMS.
- Владелец подтвердил локальное управление одним обогревателем.
- HTTPS-запрос с роутера к `https://functions.yandexcloud.net/` вернул 204.
  Это проверка сетевой доступности этого адреса, а не работающего навыка.
- Прямой канал от Алисы к роутеру пока не развёрнут.

Штатная интеграция «Алиса → HOMMYN → Ballu» зависит от доступности HOMMYN.
Она не обеспечивает поставленную задачу. Установка локального сервера сама
по себе не меняет маршрут команд существующей интеграции.

## Компоненты новой схемы

Алиса → приватный навык → обработчик в Yandex Cloud → исходящий канал
роутера → существующий `heatbridge-device` → Ballu в домашней LAN.

Обработчик навыка работает в облаке. На роутер не переносим Python,
Home Assistant или базу данных; используем имеющиеся curl, jq и C-клиент.
Порт 8765 остаётся локальным. Проброс портов и публичный IP не требуются.
Личные ссылки, токены и ключи Ballu остаются на роутере.

Для доставки рассматриваем HTTPS long polling через Yandex Message Queue,
а для подтверждений — приватные объекты в Object Storage. Роутер ждёт
сообщение в запросе к очереди, а не вызывает Cloud Function каждую секунду.
Окончательно выбирать транспорт нужно после проверки его адресов при
действующих ограничениях. Доступность одного сайта Яндекса не доказывает
доступность другого сервиса.

Yandex IoT Core не используем: сервис закрыт для новых пользователей и
по опубликованному графику прекращает работу 1 декабря 2026 года.

## Контракт выполнения

- Приватный навык привязывается через OAuth к аккаунту владельца.
- Каждый запрос содержит уникальный ID и короткий срок действия.
- Просроченные команды не выполняются после восстановления соединения.
- Повторная доставка сообщения не должна повторно включать прибор.
- Команда разрешена только для уже проверенного локально обогревателя.
- Успех возвращается после шифрованного подтверждения и совпадающего
  сообщения о новой уставке/режиме, а не после записи в облачную очередь.
- На ответ навыку отведено три секунды, включая доставку по сети.
  Без своевременного подтверждения возвращается ошибка; это не доказательство
  того, что команда не дошла. Реальное время на роутере ещё нужно измерить.
- Состояние прибора не заменяется последней отправленной командой.

## Что требуется перед развёртыванием

1. Доступ владельца в Yandex Cloud и Яндекс Диалоги.
2. Проверка платёжного аккаунта, актуальных тарифов и выбранного транспорта.
   Платные ресурсы ещё не созданы, стоимость не согласована.
3. Проверка HTTPS-адресов транспорта именно с роутера при блокировках.
   Для диагностики есть `entware/bin/heatbridge-cloud-check`.
4. Развёртывание и проверка реального обработчика, очереди, подтверждений,
   ограниченных учётных данных и исходящего клиента.
5. Испытания: команда Алисы из другой сети при недоступном HOMMYN,
   отключение связи, истечение срока команды, повторная доставка и перезапуск.

До выполнения этих проверок нельзя считать удалённое управление без HOMMYN
готовым. Работающее локальное приложение при подготовке облака не заменяем.
