# Сохранить интерфейс Алисы и защититься от устаревшего query (гибридный режим)

## Почему произошёл откат
В прежней попытке все три умения/свойства имели `retrievable:false`. Приложение «Дом с Алисой» перестало показывать текущую комнатную температуру и режим. Откат интерфейса был выполнен через `HEATBRIDGE_PUSH_STATE=0`.

Новый **опциональный** `HEATBRIDGE_HYBRID_STATE=1` НЕ выключает `retrievable`: текущая температура, режим и установленная уставка остаются в обычном ответе `query`. Одновременно включается `reportable:true`, чтобы передавать подтверждённые изменения через `/callback/state`.

При обработке `query` облачная функция читает опубликованный роутером снимок с Яндекс Диска и подтверждённый callback-ledger `/probes/alice-push-ledger.json`. Если уставка или включение были **подтверждены обогревателем и Яндекс принял уведомление HTTP 202 позже снимка**, функция подменяет только устаревшее поле. Температуру комнаты не выдумывает; не использует неподтверждённые желаемые значения. Показания остаются проверяемыми.

Это **сокращает окно отката после подтверждения**, но НЕ ГАРАНТИРУЕТ отсутствие первого отката на 3-й секунде, если подтверждение от Ballu поступает позднее. Оба пути остаются через Яндекс Диск; функция-уведомитель вызывается основной облачной функцией, не роутером. Настройку на настоящей системе сначала проверять на одной команде.

## Что обновляется
Только две функции Yandex Cloud (`ballu-alice`, `ballu-alice-notify`). ZBT WE1626, USB, прошивка, Flash-Sync, пароли и WebDAV остаются.

Сборка GitHub Actions: https://github.com/ppmonch2/zbt-we1626-openwrt/actions/runs/44803452852 (успешно, 105 тестов).

Нужен из артефакта `Ballu-Alice-Cloud-Only` внутренний ZIP `Ballu-Alice-Function.zip`. Самостоятельно не компилировать; не использовать старый ZIP.

## Порядок пробного включения
1. Убедиться, что **в основной `ballu-alice`** `HEATBRIDGE_PUSH_STATE=0`, `HEATBRIDGE_TRANSPORT=disk`, `HEATBRIDGE_ASYNC_ACTIONS=1`; оба последних не менять. В «Доме с Алисой» текущие показания и режим должны быть видны.
2. В `ballu-alice-notify` обновить исходники с нового `Ballu-Alice-Function.zip` (Python 3.12, `notify.handler`, тайм-аут 25 сек, асинхронный вызов и существующий минутный таймер оставить). Существующие переменные не удалять. Добавить `HEATBRIDGE_HYBRID_STATE=1`; `HEATBRIDGE_PUSH_STATE` этой функции можно оставить равным 1. Сохранить новую версию.
3. Тест `ballu-alice-notify` с `{}` должен вернуть `UNCHANGED` либо `OK`, но не ошибку. `OK` подтверждает приём уведомления, `UNCHANGED` — только отсутствие новых отличий.
4. В `ballu-alice` обновить исходники тем же ZIP (`skill.handler`) и добавить **`HEATBRIDGE_HYBRID_STATE=1`**. Оставить `HEATBRIDGE_PUSH_STATE=0`, `HEATBRIDGE_TRANSPORT=disk`, `HEATBRIDGE_ASYNC_ACTIONS=1` и `HEATBRIDGE_FAST_NOTIFY_FUNCTION_ID` без изменений. Сохранить новую версию.
5. В тестировании `ballu-alice`: `{"heatbridge_diagnostic":"version"}` должен показать `push_state:false`, `hybrid_state:true`, `fast_push_configured:true` и `transport:disk`.
6. Выполнить «Обновить список устройств» навыка «Дачное отопление» и **сначала убедиться в наличии ВСЕХ трёх полей карточки**, не меняя температуру.
7. Пробно изменить только один Ballu на 1 °C; записать момент отката и новой уставки. В логах `ballu-alice` найти `fast_notify_accepted`; в логах приватной функции искать подтверждённый callback. Без этого нельзя считать передачу по факту команды работающей.

## Быстрый откат
Если карточка изменится или управление нарушится, **основная `ballu-alice`** → `HEATBRIDGE_HYBRID_STATE=0` (или удалить эту переменную), `HEATBRIDGE_PUSH_STATE=0`, создать версию и обновить список устройств. Транспорт Диска не менять. Резервный таймер и `ballu-alice-notify` остаются; их необязательно отключать для восстановления UI.

## Что честно остаётся нерешённым
Если Алиса запрашивает показания до появления подтверждения и его уведомления, её ранний `query` может всё ещё вернуть старую температуру. Сохранение визуального значения **без проверки реального состояния** технически возможно, но означает выдавать запрошенную температуру за фактическую и здесь не используется. Чтобы гарантированно исключить раннюю устаревшую выдачу, понадобится отдельно реализовать защищённый статус pending и проверить, как приложение отображает неполные результаты query; этот протокол не обещает поведение карточки.
