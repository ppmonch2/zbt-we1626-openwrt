# Алиса без отката уставки: подтверждённые Push-уведомления через Яндекс Диск

**Для ZBT WE1626 + Entware + Ballu.** Это ОБЛАЧНОЕ обновление; роутер, прошивку и флешку не трогать. GitHub-ветка: `feature/heater-live-status-and-scenes`; основная рабочая конфигурация не изменена.

## Схема

Москва / «Дом с Алисой» → функция `ballu-alice` → **Яндекс Диск WebDAV** → дачный ZBT → подтверждение Ballu → **Яндекс Диск WebDAV** → приватная функция `ballu-alice-notify` → `/callback/state` → Алиса.

Дачный роутер **не обращается к Yandex Cloud Functions**, его связь с облаком проходит только через WebDAV Диска. Если Билайн разрешает именно `webdav.yandex.ru` при блокировках, такая схема может работать через белый список. Доступность обычного сайта Диска сама по себе этого не гарантирует.

Уже имеющийся агент кладёт подтверждения команд в `/acks/{batch}.json`. Новый обработчик запускается из основной функции *асинхронным вызовом Cloud Function*, ждёт ACK на Диске и только при тройном подтверждении `encrypted_session`, `command_acknowledged`, `state_echo_matches_request` уведомляет Алису о новой уставке. **Нового запроса к Ballu для этого не требуется.**

При отсутствии подтверждения новая температура не объявляется исполненной. Само Диск-соединение опрашивается несколько раз на протяжении максимум ~18 секунд. Для физического изменения на приборе, измеренной температуры и восстановления после сбоя остаётся отдельный минутный таймер; он не подменяет быстрые подтверждения команд.

## Условия

1. На даче уже работает `HEATBRIDGE_TRANSPORT=disk`, штатный `heatbridge-disk-agent` отправляет подтверждения, а `{"heatbridge_diagnostic":"disk_status"}` видит показания.
2. Навык «Дачное отопление» хотя бы раз опубликован **приватно** в Яндекс Диалогах. Черновик не принимает `/callback/state`.
3. Есть ID навыка (из Диалогов) и **OAuth-токен владельца навыка для Диалогов**. Это НЕ пароль приложения Яндекс Диска и НЕ токен Ballu. Не передавайте секреты в чат или GitHub.
4. Доступ к каталогу Yandex Cloud с Cloud Functions, сервисным аккаунтом и правами назначить `functions.functionInvoker`.

В GitHub → Actions → «Ballu Alice cloud-only package» → последняя **успешная** сборка в ветке `feature/heater-live-status-and-scenes` → Artifacts → `Ballu-Alice-Cloud-Only`. ## 1. Создание приватной функции-уведомителя

В Yandex Cloud → Cloud Functions создайте `ballu-alice-notify`:

- Среда **Python 3.12**; загрузка ZIP `Ballu-Alice-Function.zip` целиком.
- Точка входа **`notify.handler`**, память 128–256 МБ, таймаут **25 секунд**.
- **Публичные вызовы отключены**. В настройках версии включите **«Асинхронный вызов»** (в Yandex Cloud эта функция на стадии Preview), повторные попытки можно начать с 0; сохранить.
- Переменные окружения: `HEATBRIDGE_TRANSPORT=disk`, `HEATBRIDGE_PUSH_STATE=1`, `HEATBRIDGE_DISK_LOGIN`, `HEATBRIDGE_DISK_APP_PASSWORD`, `HEATBRIDGE_DISK_FOLDER=heatbridge-v1`, `HEATBRIDGE_DEVICES_JSON`, `HEATBRIDGE_OWNER_LOGIN` **или** `HEATBRIDGE_OWNER_UID`, `HEATBRIDGE_DIALOGS_SKILL_ID`, `HEATBRIDGE_DIALOGS_OAUTH_TOKEN`. Значения владельца/Диска должны совпадать с основной функцией; токены хранить только в защищённых настройках Yandex Cloud.

Сначала в «Тестирование» → `$latest` → «Без шаблона» отправьте `{}`. Ответ `{"status":"OK",...}` означает, что переданы первые подтверждённые значения; `UNCHANGED` — изменений нет. Если `CALLBACK_REJECTED`, проверьте код и публикацию навыка. **Не включайте новый режим основной функции, пока уведомитель не отправляет успешные 202 Accepted.**

## 2. Настройка сервисного аккаунта

Основной функции `ballu-alice` привяжите сервисный аккаунт, которому выдана роль **`functions.functionInvoker`** на приватную функцию `ballu-alice-notify` (или на каталог с ней, если вы используете каталог). Функция получает краткоживущий IAM-токен через штатный сервис метаданных Яндекс Облака. Секреты сервисного аккаунта в код и переменные вносить не нужно.

Подсказки из официальной документации:
- https://yandex.cloud/ru/docs/functions/operations/function/function-invoke-async
- https://yandex.cloud/ru/docs/functions/operations/function-sa

## 3. Резервный таймер

Cloud Functions → Триггеры → создать **таймер** для `ballu-alice-notify`, версия `$latest`, cron `* * * * ? *` (**каждую минуту**), сервисный аккаунт с `functions.functionInvoker`.

Он обновляет состояние, изменённое вручную на Ballu, температуру окружающего воздуха и статус доступности. **Быстрый путь для команд не ждёт этого таймера**: отдельный асинхронный вызов проверяет подтверждение команды по Диску сразу.

## 4. Обновление основной функции ballu-alice

В редакторе `ballu-alice` загрузите **тот же ZIP** `Ballu-Alice-Function.zip`, оставьте точку входа `skill.handler` и все существующие переменные.

**Сперва добавьте, но НЕ активируйте режим:**
- `HEATBRIDGE_FAST_NOTIFY_FUNCTION_ID=<ID созданной функции ballu-alice-notify>`.
- `HEATBRIDGE_DIALOGS_SKILL_ID`, `HEATBRIDGE_DIALOGS_OAUTH_TOKEN` — такие же значения, как у уведомителя.

Проверить тест `{"heatbridge_diagnostic":"version"}`: должны присутствовать `push_state: false` и `fast_push_configured: true`. Не меняйте Диск на другой транспорт.

**Только после успешного теста уведомителя и готовности IAM-права** сохраните новую версию с:
- `HEATBRIDGE_ASYNC_ACTIONS=1`
- `HEATBRIDGE_PUSH_STATE=1`
- `HEATBRIDGE_TRANSPORT=disk` (оставить)

Тест `{"heatbridge_diagnostic":"version"}` теперь должен показать `push_state: true`. В приложении «Дом с Алисой» выполните обновление списка устройств навыка «Дачное отопление». Поля умений и измерения начнут предоставляться через push `reportable:true, retrievable:false`. **При необходимости заново привяжите навык, но не удаляйте приборы до проверки.**

## 5. Проверка без поездки на дачу

1. В «Доме с Алисой» измените уставку ОДНОГО Ballu, например с 28 до 27 °C.
2. Проверьте физическое подтверждение в локальном состоянии через данные `disk_status`; роутер должен показать 27 °C.
3. Карточка Алисы не должна откатываться к старым данным `query` для этих полей; уведомление отправляется только после подтверждения. Платформа Яндекса **не гарантирует время отрисовки**, поэтому измерьте фактическое время.
4. Посмотрите журнал `ballu-alice`: `fast_notify_accepted` — асинхронный запуск принят; `fast_notify_not_accepted` — проверить IAM/асинхронный вызов/таймаут.
5. В журнале `ballu-alice-notify` и при тестах проверяйте отправку `OK`/202. Если значение не появляется, не пытайтесь обходить Диск прямым HTTPS с роутера.

Если команду на устройстве меняют физически, данные обновятся резервным таймером не чаще раза в минуту, с учётом скорости публикации состояния самим роутером.

## Откат

Если что-то не работает, **в основной функции** верните:
- `HEATBRIDGE_PUSH_STATE=0`;
- `HEATBRIDGE_ASYNC_ACTIONS` — прежнее значение (обычно отключено, если до обновления этот режим не включали).

Сохраните версию и **обновите устройства в Алисе**. Транспорт Диска и программы ZBT оставьте без изменений. Приватную функцию и таймер можно затем отключить. Помните, что одно изменение флага на сервере может не мгновенно обновить описание уже зарегистрированных устройств: при необходимости обновите список устройств навыка.

## Ограничения

- Это прототип: сборка и автоматические тесты ещё не доказывают работу Яндекс API и скорости на настоящих устройствах.
- Данные от дачи всегда идут только через WebDAV; отсутствие WebDAV при белом списке отключит удалённое управление.
- Таймер не даёт мгновенных событий на физических кнопках. Диск не имеет пригодного для этого автоматического триггера Cloud Functions, поэтому быстрые события управления включаются облачным асинхронным вызовом, а не фактом появления файла на Диске.
- Не обещаем строгие 1–3 секунды отрисовки или полного отсутствия внутренних запросов платформы Яндекса.
