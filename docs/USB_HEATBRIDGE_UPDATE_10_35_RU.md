# Обновление Ballu на USB-флешке ZBT WE1626 (Entware) — 10–35 °C

Это **обновление файлов программы в Entware**, а не прошивка роутера. Ничего не записывать в U-Boot, внутреннюю флеш-память ZBT или раздел firmware. Нельзя запускать sysupgrade/factory.bin и нельзя форматировать USB. Действующие настройки и привязки Ballu нужно сохранить.

## Какая сборка нужна

Проверенная GitHub Actions сборка: 15.11.2026, коммит `843a3883ba322bddb1597b14b740bb7225e68fe4`.

**[Скачать архив GitHub Actions (Ballu-Alice-Bridge-Preview)](https://github.com/ppmonch2/zbt-we1626-openwrt/actions/runs/43755001989/artifacts/14177514487)**. Возможно, потребуется войти в GitHub. Артефакт хранится до 29.11.2026 — скачайте заранее.

В скачанном **внешнем ZIP** находятся два отдельных ZIP-файла:
- `Ballu-Alice-Function.zip` — **только для Yandex Cloud Functions**.
- `Ballu-Alice-Router.zip` — **нужный пакет для USB-флешки**.

Также могут присутствовать TAR.GZ и файл контрольных сумм. Для установки выбирайте только `Ballu-Alice-Router.zip`, а не старый `downloads/Ballu-Alice-Router-0.2.0.zip` из ветки main: в старом пакете нет нового нативного клиента на 31–35 °C.

## До поездки

1. Скачайте внешний ZIP и распакуйте его. Сохраните `Ballu-Alice-Router.zip` отдельно.
2. Сам `Ballu-Alice-Router.zip` тоже распакуйте. Внутри должна быть **одна папка `heatbridge-alice`** с файлами `install.sh`, `SHA256SUMS`, `heatbridge-syncleo` и подпапкой `www`.
3. Проверьте, что вы можете открыть локальный интерфейс `http://192.168.1.1:8765/`, находясь в Wi-Fi роутера.
4. В Яндекс Облаке функция `ballu-alice` уже проверена: диапазон 10–35 °C виден в `skill.py`. **Повторно загружать облачный ZIP без необходимости не нужно**. `HEATBRIDGE_TRANSPORT=cloud` оставляем до проверки WebDAV с роутера.

## Перенос на флешку без извлечения из роутера

Windows обычно не открывает EXT4 напрямую — это не мешает перенести файлы на USB через SSH. **Старую папку `/opt/heatbridge-alice` не удалять и не переименовывать.**

1. Оставьте флешку ENTWARE в роутере и подключите Windows-компьютер к Wi-Fi ZBT.
2. Распакуйте `Ballu-Alice-Router.zip` на компьютере, чтобы видеть папку `heatbridge-alice`.
3. В Проводнике откройте **родительскую папку**, где видна `heatbridge-alice`; в адресной строке введите `powershell` и нажмите Enter.
4. В PowerShell выполните (порт 222 соответствует инструкции Entware; если SSH использует другой порт, примените его):

```powershell
scp -O -P 222 -r .\heatbridge-alice root@192.168.1.1:/opt/heatbridge-alice-new
```

5. Введите пароль пользователя root от Entware. Команда копирует файлы по SSH прямо на USB, без Windows-доступа к файловой системе EXT4. Папка назначения `heatbridge-alice-new` должна **ещё не существовать**, иначе возможно появление лишнего уровня вложенности.
6. Если SSH/SCP выдаёт ошибку, сохраните её текст. Не форматируйте флешку, не удаляйте старую папку и не пытайтесь использовать бинарник прошивки.

**Альтернатива:** если включён сетевой файловый доступ к ENTWARE, можно загрузить файлы туда и без SCP, но также **под новым именем папки**, не заменяя работающие файлы вручную.

## Проверка и установка через существующее SSH-подключение Entware

Подключитесь к ранее настроенному SSH `endware` / Entware под `root`. Проверьте расположение:

```sh
ls -l /opt/heatbridge-alice-new/install.sh /opt/heatbridge-alice-new/SHA256SUMS /opt/heatbridge-alice-new/heatbridge-syncleo
```

Если любой файл отсутствует — исправьте расположение папки до продолжения. После копирования через Windows могут не сохраниться права на выполнение:

```sh
chmod 755 /opt/heatbridge-alice-new/heatbridge-syncleo
cd /opt/heatbridge-alice
sha256sum -c SHA256SUMS
```

Продолжайте, только когда **все проверки контрольных сумм прошли успешно**. Запустите:

```sh
/opt/bin/sh /opt/heatbridge-alice-new/install.sh
```

Ожидаемый результат: `Files installed. Agent was NOT started.`

Установщик проверяет, что новый MIPS-клиент допускает 35 °C, затем устанавливает новый бинарник, обновляет shell-скрипты и страницу управления. Старый бинарник сохраняется как `/opt/libexec/heatbridge-syncleo.before-range-10-35`. Конфигурации, токены обогревателей и прошивка роутера не заменяются. Если установка вывела ошибку, **не переходите к запуску канала Диска**; сохраните текст ошибки.

## Проверка работы локального интерфейса

Откройте `http://192.168.1.1:8765/` (при необходимости обновите страницу без кеша).

- У каждого настроенного Ballu должны отображаться уставка, измеренная температура и режим **при наличии свежих данных**. Если датчик не ответил или данные устарели, программа не должна выдавать старые показания за текущие.
- Допустимые уставки: **10–35 °C**, с шагом 1 °C.
- Сначала проверьте команду на одном обогревателе и сравните с его дисплеем. Без подтверждения команду не повторяйте автоматически.
- Кнопки «+»/«−» в приложении «Дом с Алисой» относятся к собственной интеграции **«Дачное отопление»**, а не к старым карточкам HOMMYN.

## Включение канала через Яндекс Диск

1. Откройте `http://192.168.1.1:8765/disk.html`. Введите логин Яндекс Диска, **пароль приложения WebDAV** и папку `heatbridge-v1`. Не используйте основной пароль Яндекс ID.
2. Нажмите «Сохранить настройки», затем **«Проверить запись и чтение»**. Дождитесь подтверждения, что файл записан, прочитан и удалён. Если результат отрицательный, ничего дальше не включайте.
3. Нажмите **«Запустить через Диск»**, затем «Обновить статус». Убедитесь, что программа запущена и Диск отвечает.
4. **Только теперь** в Yandex Cloud → Cloud Functions → `ballu-alice` смените `HEATBRIDGE_TRANSPORT` с `cloud` на `disk` и сохраните версию. Существующие переменные и настройки функции оставьте.
5. Для диагностики в редакторе функции выберите «Тестирование» → `$latest` → «Без шаблона». Проверьте запросы:

```json
{"heatbridge_diagnostic":"disk_probe"}
```

Ожидается `status: "OK"` и `write_read: true` — облачная функция записала проверочное значение через WebDAV и прочитала его обратно. Для диагностики используется один перезаписываемый файл `probes/cloud-check.json`; удаление через WebDAV не является условием передачи команд. Затем:

```json
{"heatbridge_diagnostic":"disk_status"}
```

Ожидаются показания доступных h1–h4; `NO_ROUTER_STATE` означает, что файл показаний ещё не опубликован. Обновите список устройств «Дачное отопление» в приложении «Дом с Алисой», после чего по одному проверьте уставку, кнопки «+»/«−», включение и сценарий для четырёх устройств. Сопоставьте результаты с дисплеями Ballu.

## Если Яндекс Диск не работает

Оставьте функцию в режиме `cloud` или верните `HEATBRIDGE_TRANSPORT=cloud` и сохраните версию. На странице `disk.html` выберите «Включить прежнюю очередь». Это возврат **канала связи**; не полная отмена обновления файлов. Если не работает локальное управление, не пытайтесь перепрошивать роутер: сохраните сообщение об ошибке и свяжитесь со мной для проверки.

## Ограничения

- Успешные GitHub Actions и тесты QEMU **не подтверждают** работу на реальном ZBT/Билайне.
- Доступ к приложению Яндекс Диска не доказывает доступность WebDAV `webdav.yandex.ru` при ограничении мобильного интернета.
- Файлы и кнопки не дают удалённый SSH-доступ к роутеру — это отдельная настройка.
- Код функции по-прежнему отвечает диагностикой `version: "0.2.0"`; для отличия сборок проверяйте объявленный диапазон 10–35 °C и идентификатор GitHub Actions.
