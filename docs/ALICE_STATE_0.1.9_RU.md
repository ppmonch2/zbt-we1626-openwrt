# Два показания Ballu в Алисе: облако 0.1.9, агент 0.1.3

Реализованы оба разных значения:

| Интерфейс Алисы | Протокол | Источник обогревателя |
| --- | --- | --- |
| Уставка в карточке | capabilities.range / temperature | reported_target |
| Температура воздуха в списке | properties.float / temperature | current_temperature |

Уставка не подменяется температурой воздуха или последней отправленной командой.
Возвращается также включение/выключение из реального device_mode.
Схема свойства соответствует [документации Алисы](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/float).

## Как поступают данные

Агент запускает heatbridge-alice-state. Он последовательно читает h1–h4 через
существующий heatbridge-device read — тот же путь, что у кнопки «Проверить состояние».
Используется уже установленный зашифрованный клиент; менять бинарник, прошивку или
токены Ballu не нужно. Между приборами пауза 2 секунды, между циклами ещё 2 секунды.
С существующим клиентом цикл четырёх доступных приборов обычно займёт порядка
20–30 секунд; это расчёт по текущим тайм-аутам, не замер на оборудовании владельца.

Это периодическое обновление, не непрерывная трансляция и не гарантированно новый
опрос по каждому открытию карточки. При открытии Алиса получает последний свежий
снимок. Чтобы список Алисы узнал о новом свойстве, нужно обновить устройства
провайдера после установки агента.

Подписанный PUT публикует один закрытый объект acks/state-v1.json в существующем
бакете. После каждого опроса обновляется объект всех устройств; он содержит только
идентификаторы h1–h4, время, состояние соединения, уставку, измеренную температуру
и режим. Ключи и токены в него не попадают. Облако делает один подписанный GET для
всей группы, после проверки владельца аккаунта. Имеющихся storage.uploader у
роутера и storage.viewer у функции достаточно, новых прав не требуется.

Публикации создают регулярные операции Object Storage и исходящий трафик роутера.
Их частота зависит от времени чтения и количества настроенных приборов.

Если хотя бы обязательное показание старше 90 секунд, недопустимо, отсутствует или
прибор не ответил, функция возвращает DEVICE_UNREACHABLE для этого прибора.
Допускается до 5 секунд расхождения часов вперёд. Время каждого поля хранится
отдельно: подтверждение новой уставки не делает старую температуру датчика свежей.
Недоступность одного обогревателя не скрывает показания остальных.

## Приоритет команд

Обёртка heatbridge-device блокирует отдельный прибор, а не все четыре сразу.
Команда тому же прибору может прервать только фоновое чтение. Проверяется PID и
его командная строка; прерываются также дочерние процессы чтения. Явный опрос
из локального интерфейса и уже выполняющаяся команда не прерываются.
Снимки сохраняются атомарно с правами 600. Секреты по-прежнему идут в клиент через stdin.

Это ещё не полное исправление групповых сценариев: основной агент всё ещё
исполняет сообщения очереди последовательно. Прежняя защита от повторного
выполнения и проверка настоящего подтверждения команды сохранены.

## Что можно установить сейчас, находясь вне дачи

1. Скачать downloads/Ballu-Alice-Function-0.1.9.zip.
2. Yandex Cloud → Cloud Functions → ballu-alice → Редактор → загрузить ZIP.
3. Сохранить Python 3.12, точку входа skill.handler, существующие переменные
   окружения, сервисный аккаунт и тайм-аут 3 секунды. Создать версию.
4. Тестирование → $latest → Без шаблона:

```json
{"heatbridge_diagnostic":"version"}
```

Ожидаются version: "0.1.9", state_reporting: "auto",
state_router_min_version: "0.1.3". Эта проверка не включает обогреватель.

Облако совместимо с агентом 0.1.2: пока объекта состояний нет, discovery не объявляет
новые возможности и query сохраняет прежний ответ. Само обновление облака не
начнёт опрашивать приватный адрес 192.168.1.1. Установить агент через команды Алисы нельзя.

## При следующем доступе к роутеру

Нужен downloads/Ballu-Alice-Router-0.1.3.tar.gz и его .sha256 из того же выпуска.
Проверить SHA256, распаковать архив в /opt и запустить:

```sh
sh /opt/heatbridge-alice/install.sh
/opt/etc/init.d/S85heatbridge-alice start
```

Установщик остановит прежний агент, сохранит резервную копию обёртки как
/opt/bin/heatbridge-device.before-alice-state и заменит только скрипты.
Настройки, секреты, native-клиент и локальный веб-интерфейс сохраняются.
Если выполняется операция старого локального интерфейса, установщик попросит
дождаться её завершения. Не запускать две установки одновременно.

Подождать полный цикл опроса. В Алисе обновить список устройств провайдера
«Дачное отопление», затем открыть карточки всех четырёх приборов.
Проверить отдельно уставку и температуру воздуха, включая выключенный прибор.

Диагностика на месте:

```sh
cat /tmp/heatbridge-alice/telemetry/status
cat /tmp/heatbridge-alice/telemetry/upload.json
```

Первый файл должен содержать published. Второй содержит только разрешённые
показания, без секретов. Состояние published подтверждает загрузку объекта,
а не доступность каждого обогревателя — для этого смотреть online и время полей.

Откат облака: ZIP 0.1.8 с прежними переменными. Откат роутера: остановить агент,
восстановить /opt/bin/heatbridge-device из .before-alice-state, установить архив
агента 0.1.2 и запустить его. Облако 0.1.8 игнорирует оставшийся объект состояний.

## Граница проверки

Автотесты проверяют раздельные показания, все четыре ID, давность и ошибки,
авторизацию, публикацию без секретов, приоритет команд, очистку процессов,
частичные ответы и сохранение времени измерения. На настоящем роутере владельца
этот выпуск ещё не установлен: фактическое время цикла, расход памяти и поведение
карточек Алисы требуют проверки после установки, включая перезапуск роутера.
