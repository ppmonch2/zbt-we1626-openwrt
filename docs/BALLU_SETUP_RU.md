# Ballu: прямой локальный Syncleo v3

## Текущее состояние

На сети владельца обнаружены два устройства devtype=46, firmware=1.43, protocol=3,
public key advertised. Это подтверждение объявления сервиса, но ещё не авторизации
или работы команд. Свежий образ включает native-клиент heatbridge-syncleo на C и
libopenssl; Python и Home Assistant в образ не включаются. MQTT, ca-bundle и tcpdump
из базовой комплектации убраны ради памяти.

Чтение выполняет только шифрованный handshake и ACK входящих сообщений: без смены
DNS, режима, питания, времени, Wi-Fi или настроек MQTT. Отправка меняет только уставку
5–30 °C, не включает выключенный обогреватель. ACK не доказывает физический нагрев.

После установки нужно локально сохранить для каждого h1..h4 поля ip, port,
public_key и token в /etc/config/heatbridge (chmod 600). Публичный ключ и порт берутся
из текущего mDNS: после перезапуска модуля они могут измениться. Они не должны
подставляться по старому снимку. Токен берётся из личной ссылки «Поделиться».
Никаких настоящих токенов, ключей и адресов в образе нет.

Для теста чтения: mode=syncleo, затем heatbridge-syncleo read h1. Отправка заблокирована,
пока для конкретного прибора protocol_verified не установлен в 1 после испытания.
Если на приборе не включена передача состояния после handshake, чтение может
установить сессию, но не получить уставку; интерфейс не выдаёт это за успешное чтение.
Автоматическое обновление endpoint/public key из mDNS пока не реализовано.

Клиент компилируется; независимая проверка криптографии без сети проходит.
Полные тесты с UDP-имитатором запускаются в GitHub CI. Проверки на физических Ballu
ещё не было. Прежде чем прошивать, нужно дождаться сборки и проверки размера.

# Ballu: подготовка одной установки OpenWrt

Эта версия включает MQTT с TLS, сертификаты доверенных центров, mDNS-обнаружение,
средства диагностики и изменяемый сервер Heat Bridge. Это подготовка транспорта;
совместимость с конкретными BCT/EVU-4I ещё не проверена на устройствах владельца.

## Что проверено по исходникам

- samoswall/polaris-mqtt описывает MQTT-вариант Transformer DI 4.0 типа 846:
  https://github.com/samoswall/polaris-mqtt/blob/main/custom_components/polaris/const.py
  Для него указаны control/temperature и state/temperature, десятичная уставка.
- Пользовательский MQTT из настроек HOMMYN использует другую структуру:
  https://github.com/udocs-ru/hommyn_local_mqtt
  Её нельзя подменять облачными топиками. Также нельзя переносить режимы
  кондиционеров (например, heat=4) на конвектор без проверки.
- Есть локальный UDP Syncleo, но готовая библиотека требует Python >=3.14.2
  и cryptography: https://github.com/DeKaN/pysyncleo
  Она не встроена в этот образ с флеш-памятью 8 МиБ.

Ни одна из этих ссылок не доказывает поддержку конкретной версии Wi-Fi-модуля.
До определения типа устройства и протокола оставляем mode=simulation.
Отсутствие управления в HOMMYN без интернета не исключает локальный протокол.

## Первое подключение

После установки задать пароль root и WPA2/WPA3, подключить обогреватели к Wi-Fi
роутера. Запустить через SSH (можно с Android):

```
/etc/init.d/umdns start
heatbridge-discover
```

В выводе ищем _syncleo._udp, devtype, protocol и firmware. Не публиковать
токены, полный дамп или конфигурацию с паролями. Ссылки «Поделиться» содержат
секретный token; для определения типа достаточно числа после rusclimate/.

## Подключение MQTT после проверки протокола

Сначала проверить наличие пользовательского MQTT в HOMMYN. Если он есть,
можно указать отдельный локальный брокер и проверить реальные выходные топики.
Встроенный брокер Mosquitto по умолчанию выключен; для него отдельно настроить
listener на LAN, аутентификацию, ACL и при необходимости TLS, затем запустить.
Нельзя включать anonymous listener на всех интерфейсах.

Не перенаправлять mqtt.cloud.rusklimat.ru на роутер автоматически: облачный MQTT
может требовать TLS, а перенаправление способно отключить штатное приложение.
Настройка внешнего MQTT не означает подтверждённую поддержку облачных команд.

После получения действительных топиков и проверки формата уставки задать через
UCI локально (пример ниже содержит только условные значения):

```
uci set heatbridge.main.mqtt_host='192.168.1.1'
uci set heatbridge.main.mqtt_port='1883'
uci set heatbridge.main.allow_plain_lan='1'
# username/password задаются локально, если они требуются брокеру.
# Для TLS: mqtt_tls=1, mqtt_port=8883 и DNS-имя из сертификата в mqtt_host.
# TLS проверяет цепочку и имя сервера; отключения проверки сертификата нет.
uci set heatbridge.h1.command_topic='REPLACE/with/verified/command/topic'
uci set heatbridge.h1.state_topic='REPLACE/with/verified/state/topic'
uci set heatbridge.h1.protocol_verified='1'
uci set heatbridge.main.mode='mqtt'
uci commit heatbridge
chmod 600 /etc/config/heatbridge
heatbridge-enable
```

Повторить привязку h2, h3, h4 после проверки каждого прибора. Не задавать
protocol_verified=1 до определения реальных топиков и десятичного формата 5–30 °C.
Транспорт не поддерживает произвольные бинарные/JSON payload; другая кодировка
потребует обновления программы, а не повторной прошивки.

В интерфейсе http://192.168.1.1:8765/ кнопка «Отправить» публикует уставку с QoS 1
без retain. Она не включает питание и не меняет режим конвектора. Режимы «Уехал»
и «Еду на дачу» отправляют только 12/22 °C; выключенный прибор остаётся выключен.
Публикация брокеру не считается подтверждением прибора или фактического нагрева.
Кнопка чтения ожидает только свежие сообщения (retained игнорируются); отсутствие
сообщения за две секунды не доказывает, что устройство отключено.
При ошибке отдельного прибора его уставка не сохраняется как успешно отправленная;
остальные приборы могут получить свои команды — результат отображается отдельно.

Откат транспорта без перепрошивки:

```
uci set heatbridge.main.mode='simulation'
uci commit heatbridge
```

## Дальнейшие изменения без прошивки

Сборка создаёт heatbridge-app.tar.gz и heatbridge-app.sha256. Архив содержит только
веб-сервер и его инструменты; не включает U-Boot, ядро, сетевые настройки и секреты.
На уже установленной совместимой OpenWrt перенести оба файла в /tmp по SCP/SFTP,
проверить их и установить:

```
cd /tmp
sha256sum -c heatbridge-app.sha256
tar -tzf heatbridge-app.tar.gz
# Продолжать только после успешной проверки и проверки списка файлов.
tar -xzf heatbridge-app.tar.gz -C /
```

Архив не устанавливает отсутствующие системные зависимости. Его нужно собирать из
корня исходного репозитория командой python3 boards/make_heatbridge_update.py.
Перепрошивка нужна при замене ядра/драйверов; корректировки протокола в скриптах,
адресов, токенов, топиков и интерфейса выполняются отдельно. Наличие места в
записываемом overlay после установки также нужно проверить командой df -h.

## Ограничение первой установки

Состав ПО не подтверждает загрузку на конкретном U-Boot. Прежние образы Omni II
и WE2026 не использовать: их разметка отличается. Аудит нового образа проверяет
размер, CRC, разметку, пакеты и файлы; реальные GPIO и загрузчик остаются непроверены.
