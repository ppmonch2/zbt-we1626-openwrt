# Приватная Алиса → локальный Ballu без HOMMYN

Код подготовлен для проверки. Облачные ресурсы и привязка навыка ещё не созданы;
реальная доставка через Яндекс и задержка на роутере ещё не проверены.
Работающее локальное приложение обновлять или переустанавливать не требуется.

## Состав

- `alice/skill.py`: приватный навык умного дома, JSON-RPC для Cloud Functions.
- `alice/yandex_services.py`: проверка владельца через Яндекс ID, подписанный
  HTTPS API очереди YMQ и чтение подтверждений из приватного Object Storage.
- `router/heatbridge-alice`: исходящее ожидание команды через HTTPS long polling.
- `router/heatbridge-alice-worker`: проверка срока, локальной привязки и результата;
  сохраняет на USB обработанные ID, чтобы не повторять команду при доставке дубля.
- `router/S85heatbridge-alice`: отдельный автозапуск. Локальный сервер не заменяет.
- `package.py`: сборка двух небольших архивов без ключей и частных настроек.

На роутере используются уже установленные shell, curl, jq и C-клиент Ballu.
Поддерживается сборка Entware jq без Oniguruma: проверки символов используют
только операции с массивами кодов ASCII, без регулярных выражений.
Python и облачная обработка работают вне роутера. Реальное добавочное потребление
ОЗУ нужно замерить после запуска; число не оценивалось на глаз.

Первый вариант поддерживает целую температуру 5–30 °C и включение/выключение.
Включение выбирает режим «Комфорт». Установка температуры не включает выключенный
прибор. Голосовые относительные изменения («прибавь два градуса») пока отклоняются.
Умения объявлены `retrievable:false`: измеренную температуру в Алису этот вариант
ещё не передаёт и последнюю команду за текущее состояние не выдаёт.

## Требования к облаку

До создания ресурсов проверить платёжный аккаунт, стоимость и доступность
`functions.yandexcloud.net`, `message-queue.api.cloud.yandex.net` и
`storage.yandexcloud.net` с роутера во время ограничений.

Ресурсы следует разместить в отдельном каталоге `ballu-heatbridge`, чтобы роли
сервисных аккаунтов не давали доступ к другим очередям и данным владельца:

1. Стандартная очередь команд YMQ: long polling 20 секунд, минимальный срок
   хранения 60 секунд. Само сообщение действует меньше трёх секунд.
2. Приватный бакет подтверждений. Публичный доступ выключен. Объекты `acks/`
   автоматически удалять через сутки правилом lifecycle. Объём ограничить.
3. Два сервисных аккаунта с разными статическими ключами:
   облачный обработчик — `ymq.writer` и чтение из бакета;
   роутер — `ymq.reader` и запись подтверждений в бакет.
   Роли YMQ назначаются на каталог; права Object Storage ограничить своим бакетом.
4. Cloud Function Python 3.12, 128 МиБ, обработчик `skill.handler`, timeout 3 сек.
   Архив `Ballu-Alice-Function.zip`. Не включать плановые вызовы функции.
5. Приватный неофициальный навык в Яндекс Диалогах, backend — эта функция.
   Привязка аккаунта через Яндекс OAuth с правом `login:info`;
   redirect URI `https://social.yandex.net/broker/redirect`.

Переменные окружения функции:

| Имя | Значение |
| --- | --- |
| `HEATBRIDGE_OWNER_LOGIN` | Основной логин владельца в Яндексе, без `@yandex.ru` |
| `HEATBRIDGE_OWNER_UID` | Необязательно: числовой ID владельца вместо логина; если указан, имеет приоритет |
| `HEATBRIDGE_DEVICES_JSON` | Например `{"h2":"Мансарда"}`; только проверенные приборы |
| `HEATBRIDGE_QUEUE_URL` | Полный HTTPS URL своей очереди |
| `HEATBRIDGE_ACK_BUCKET` | Имя приватного бакета |
| `AWS_ACCESS_KEY_ID` | Ключ сервисного аккаунта обработчика |
| `AWS_SECRET_ACCESS_KEY` | Секрет этого ключа |

Ключи создавать и хранить в аккаунте владельца; в GitHub, сообщения и скриншоты
их не включать. Код не выводит окружение, тело запроса с токеном или ответы
облачных API в логи. В журнал попадает только проверенный request_id.
Логин сверяется с ответом API Яндекс ID по действительному OAuth-токену.
Одного знания логина для входа недостаточно. Пустой логин и ID запрещены:
автоматического разрешения доступа первому вошедшему пользователю нет.

В `/opt/etc/heatbridge/alice.json` на роутере нужны поля `queue_url`, `ack_bucket`,
`access_key`, `secret_key`. Последние два принадлежат **аккаунту роутера**,
а не обработчика. Права файла 0600, каталога 0700. Личные ссылки и токены Ballu
в этот файл и в облако не копируются.

## Проверка и установка

Локально: `python3 -m unittest discover -s tests -p test_alice.py -v`.
Сборка: `python3 cloud/package.py`. Архивы появляются в `output-alice/`.
Это не создаёт ресурсы Яндекса и не выполняет платных действий.

На роутере распаковать архив в `/opt`, создать приватную конфигурацию и выполнить
`sh /opt/heatbridge-alice/install.sh`. Установщик сам клиент **не запускает**.
После проверки настроек запускать `/opt/etc/init.d/S85heatbridge-alice start`.

Сначала подключить к навыку один прибор, затем проверить команду из внешней сети
с отличимым тестовым именем, например «Локальная мансарда», чтобы Алиса не
выбрала старый экземпляр HOMMYN с таким же названием. После успешной проверки
убрать старые экземпляры из «Дома с Алисой» и переименовать новые. Сам прибор
из HOMMYN не удалять: локальная авторизация использует его существующую привязку.

Проверить доставку
при заблокированном HOMMYN и доступном Яндексе. Успех принимается только после
шифрованного ACK и соответствующей уставки/режима от Ballu. Таймаут означает
отсутствие подтверждения; команда могла дойти. Автоматически её не повторять.

Необходимо проверить: действительные подписи AWS SigV4 в Яндексе, OAuth,
фактическую задержку меньше трёх секунд, автозапуск, дубликаты сообщений,
просроченную команду после потери связи, отказ при неверном аккаунте и память.
На роутере должны быть правильные дата/время для TLS и проверки сроков.

## Расходы

При постоянном ожидании по 20 секунд получится примерно 129 600 запросов чтения
за 30 дней без команд и переподключений. В лимит YMQ 100 000 бесплатных запросов
это целиком не укладывается. Добавляются операции очереди и хранилища при
командах, вызовы функции, небольшое хранение и трафик. Бесплатность не обещается;
актуальные цены и бюджет нужно проверить до развёртывания. При сбое связи есть
пауза пять секунд перед повтором; функция не висит в ожидании круглые сутки.
