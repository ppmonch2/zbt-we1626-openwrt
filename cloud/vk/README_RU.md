# VK как альтернативный канал связи дачного ZBT — первый этап, без управления отоплением

## Цель

Проверить двусторонний обмен: Москва/Yandex Cloud → **api.vk.com** → дачный роутер ZBT → **api.vk.com** → Yandex Cloud.

Это **экспериментальный безопасный этап**. Скрипты не обращаются к Ballu, не включают и не выключают устройства, не меняют настройки WebDAV или Алисы. Существующий Яндекс Диск остаётся работающим транспортом.

VK есть в белом списке Билайна, **но доступность именно api.vk.com во время ограничений не гарантирована**. Проверка в обычное время подтверждает корректность программы и доступы, но не обходит ограничения оператора.

## Почему сообщения сообщества

Для официального MAX Bot API владелец не может пройти требуемую верификацию бизнеса. Для VK-сообщества можно создать ключ API с правом «Сообщения сообщества» в настройках обычного личного VK-аккаунта.

Для пилота не требуется Long Poll-сервер с отдельным доменом. Используются только **две документированные операции на одном домене**:
- `https://api.vk.com/method/messages.send` — отправить сообщение из сообщества владельцу;
- `https://api.vk.com/method/messages.getHistory` — прочесть историю этого диалога.

Важно: доступность сайта vk.com НЕ гарантирует доступности api.vk.com. После испытаний при реальной блокировке решим, подходит ли эта схема.

Собственные продукты Билайна: персональное «Облако билайн» входит в белый список, но подтверждённого внешнего API управления файлами для частного лица мы не нашли. Бизнес-продукт beeline cloud S3 имеет API, но это другое решение с отдельным подключением, а его API также не гарантирован белым списком.

## Шаг 1. Создать своё VK-сообщество

1. В своём личном VK открой «Сообщества» → «Создать сообщество». Название, например, «Дача: канал отопления». Не публикуй в нём адрес дачи, пароли или другие личные данные.
2. **Управление → Сообщения**: включи сообщения сообщества.
3. От своего личного аккаунта открой диалог с этим сообществом и отправь короткое сообщение, чтобы разрешить переписку.
4. **Управление → Работа с API → Ключи доступа → Создать ключ**. Отметь только разрешение **«Сообщения сообщества»**. Скопируй ключ в надёжное место. **Не присылай ключ в чат, не загружай его в GitHub.**
5. Запиши **числовой ID сообщества** и **числовой ID своего профиля VK**. Это разные числа.

Если кнопки называются немного иначе, ищи в настройках сообщества «Сообщения» и «Работа с API».

## Шаг 2. Скачать две программы

GitHub → Actions → **VK mailbox transport pilot checks** → последний успешный запуск из ветки `feature/vk-transport-pilot` → Artifacts → **VK-Mailbox-Pilot**.

Внутри:
- `VK-Pilot-Cloud.zip` — для отдельной диагностической функции в Yandex Cloud, точка входа `vk_pilot.handler`;
- `VK-Pilot-Router.zip` — для USB/Entware на ZBT, **НЕ прошивка**.

Ссылка на запуски: https://github.com/ppmonch2/zbt-we1626-openwrt/actions/workflows/vk-pilot-check.yml?query=branch%3Afeature%2Fvk-transport-pilot

## Шаг 3. Создать секрет для подписи

Нужен **один случайный секрет из 32 байт в hex, то есть 64 символа**. Он используется как HMAC для проверки, что сообщения не подделаны. Его надо хранить только в переменных облачной функции и закрытом файле конфигурации Entware. Не присылай в чат или на GitHub.

Сгенерировать через существующий SSH Entware (когда будешь подключён к ZBT):
```sh
head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n'; echo
```

## Шаг 4. Облачная проверка (без изменений ballu-alice)

В Yandex Cloud создаётся отдельная функция `ballu-vk-pilot`:
- Python 3.12, ZIP `VK-Pilot-Cloud.zip`, обработчик `vk_pilot.handler`, таймаут 10–15 секунд;
- переменные `HB_VK_TOKEN` (ключ сообщества), `HB_VK_GROUP_ID` (числовой ID группы), `HB_VK_PEER_ID` (числовой ID личного профиля) и `HB_VK_HMAC_KEY` (64-символьный секрет);
- доступ к функции только у владельца; включать публичный доступ не нужно.

Проверь в «Тестирование» → `$latest` → «Без шаблона»:
```json
{"vk_pilot":"check_api"}
```
`status: "OK"` означает, что облако действительно может прочитать историю диалога через VK API.

Далее:
```json
{"vk_pilot":"send_ping"}
```
Ответ содержит `status: "PING_SENT"` и `nonce`. В диалоге VK появится подписанное техническое сообщение. **Это не команда обогревателю**.

## Шаг 5. Роутер: ответ без управления Ballu

Только когда оба предыдущих теста работают, из `VK-Pilot-Router.zip` получи `heatbridge-vk-pilot.sh` и `vk-pilot.example.json`. На компьютере сделай **локальную** копию `vk-pilot.example.json` под именем `vk-pilot.json` и заполни в ней реальные значения ключа/ID/секрета. НЕ размещай её в GitHub и не пересылай в чат.

Через веб-интерфейс файлов роутера загрузи `VK-Pilot-Router.zip` и отдельно `vk-pilot.json` в корень ENTWARE. Через SSH `endware`:

```sh
mkdir -p /opt/vk-pilot
cd /opt/vk-pilot
unzip /opt/VK-Pilot-Router.zip
sha256sum -c SHA256SUMS
cp /opt/vk-pilot.json /opt/etc/heatbridge/vk-pilot.json
chmod 600 /opt/etc/heatbridge/vk-pilot.json
/opt/bin/sh /opt/vk-pilot/heatbridge-vk-pilot.sh --once
```

Если `unzip` или `openssl` отсутствуют, **не устанавливай ничего наугад**: сообщи точную ошибку. Скрипт сам проверяет обязательные зависимости и остановится. Файлы Entware, Алисы и WebDAV не заменяются.

При получении правильного подписанного PING (не старше 120 секунд) роутер отправит PONG. Затем снова в облачной функции:
```json
{"vk_pilot":"check_pong"}
```
Ожидаемый результат: `PONG_RECEIVED`. При `NO_PONG_YET` проверяем ошибки, токены, доступность сети и время, но не меняем управление отоплением.

## Следующая стадия

**Только после подтверждённого PING/PONG** через один и тот же VK-диалог дорабатываем интерфейс:
- облачная `ballu-alice` публикует команду в VK с уникальным ID и коротким временем действия;
- ZBT принимает команду, проверяет HMAC, срок, целевое устройство и защиту от повтора; вызывает уже проверенный локальный `heatbridge-device`;
- фактическое подтверждение и состояния отправляются обратно в VK, а облако сообщает результат Алисе;
- Яндекс Диск остаётся доступным как исходный канал; переключение между VK и Диском — отдельная настройка, а не замена прошивки.

Пока это **пилот транспорта**, а не готовый вариант удалённого отопления. Не следует полагаться на VK до теста при ограничениях Билайна и подтверждения работы управления.
