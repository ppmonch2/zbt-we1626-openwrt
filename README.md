# Dacha Heat Bridge: OpenWrt для ZBT WE1626

## Текущая разработка: отдельный профиль WE1626 / MT7620N

В каталоге [boards/](boards/) создан новый экспериментальный профиль `zbtlink_zbt-we1626-ndms`, который **собирается из исходников OpenWrt 25.12.6**. Он использует подтверждённый размер раздела Firmware **0x720000**, оставляет конфигурационные разделы NDMS за пределами `firmware` и не изменяет U-Boot.

- [Автоматическая сборка нового профиля](https://github.com/ppmonch2/zbt-we1626-openwrt/actions/workflows/we1626-custom.yml).
- [Инструкция по проверке загрузчика, установке и восстановлению](docs/BOOTLOADER_FLASH_PLAN_RU.md).
- [Аудит аппаратных сведений](docs/HARDWARE_VERIFICATION_RU.md).

Модификацию **MT7620N мы принимаем как рабочую гипотезу по решению владельца**. Требуется проверка, как фактический U-Boot читает ядро: у сохранённой NDMS оно меньше 0x130000, а современный OpenWrt использует более крупный uImage. Совпадение заводского контейнера `ZNBG` не гарантирует загрузку. Даже если новая сборка будет успешна, это **не разрешение прошивать на даче без работающего плана восстановления**.

## ВАЖНО: аппаратная проверка 14.11.2026 — текущие образы НЕ СОВМЕСТИМЫ ПО РАЗМЕТКЕ

Получен вывод `more proc:/mtd` с реально работающего ZBT WE1626 под NDMS:
- `U-Boot` 0x30000, `U-Config` 0x10000, `RF-EEPROM` 0x10000;
- `Firmware` (mtd5) **0x720000** по адресу 0x50000..0x770000;
- `Config` (mtd6) 0x10000 по адресу 0x770000..0x780000;
- `Storage` (mtd7) 0x80000 по адресу 0x780000..0x800000;
- всего `Full` 0x800000 (8 MiB); CPU MediaTek MT7620 SoC; командная строка ядра `console=ttyS0,57600n8`.

Текущий профиль **zyxel_keenetic-omni-ii** объявляет `firmware` 0x7b0000 от 0x50000 до 0x800000 — **заходит на Config и Storage** на 0x90000 (576 KiB). Профиль **zbtlink_zbt-we2026** объявляет `firmware` 0x760000, также заходит в зарезервированную зону на 0x40000 (256 KiB). Образ Omni II может физически помещаться в mtd5, но ядро использует неправильную карту памяти после установки.

**НЕ ЗАЛИВАТЬ никакой из текущих образов `factory.bin` или `sysupgrade.bin` через Keenetic. Успешный CI не подтверждает аппаратную совместимость.** Требуется индивидуальное DTS / профиль с разделом 0x720000, проверка точной модели SoC, USB, карты Ethernet, GPIO и способа первичной установки через существующий загрузчик. Этот репозиторий сохраняется для разработки и диагностики, не для установки текущих бинарников.


**Экспериментальные образы. Совместимость с физической платой ZBT WE1626 и установленным U-Boot не подтверждена; возможен полный отказ роутера.**

## Варианты OpenWrt 25.12.6

- `heat-lite` — профиль WE2026, `sysupgrade.bin`, без LuCI (не подходит для первичной настройки только с телефона).
- `heat-webui` — профиль WE2026, `sysupgrade.bin`, с LuCI.
- `omni2-firstflash` — профиль ZyXEL Keenetic Omni II, `factory.bin`, без LuCI.
- `omni2-firstflash-webui` — профиль ZyXEL Keenetic Omni II, **`factory.bin` с LuCI**, кандидат для экспериментального первого перехода из NDMS с последующей настройкой через Android.

Совпадение формата `factory.bin` с резервной прошивкой NDMS **не доказывает совместимость железа**.

В образах: USB ZTE CDC Ethernet, локальный Dacha Heat Bridge для четырёх BALLU, настройки UCI и MQTT без TLS. **Команды реальным BALLU не отправляются**: локальный протокол DI 4.0 не подтверждён.

## Стандартный первый вход без LAN и USB-флешки

На первом запуске прошивка включает Wi-Fi **`DachaHeat-Setup` без пароля**, локальный адрес **`192.168.1.1`**, LuCI в вариантах `webui`. Первоначальный root-пароль не установлен (стандартный первый вход OpenWrt).

**Это незащищённый режим первоначальной настройки.** Интернет ZTE (интерфейс `wanusb`) и веб-сервер отопления по умолчанию отключены. Сначала установите пароль root и WPA2/WPA3 на Wi-Fi, затем включите интернет и Dacha Heat Bridge.

- [Порядок первого входа с телефона](docs/OPEN_WIFI_FIRSTBOOT_RU.md)
- [Восстановление и загрузчик](docs/RECOVERY_RU.md)
- [Функции Heat Bridge](docs/HEATBRIDGE_RU.md)

Никаких паролей в публичные GitHub Actions/ZIP не встроено. Пароли задаются пользователем локально с телефона.

## Ограничения и риски

- Первый запуск по Wi-Fi **не решает способ физической установки** OpenWrt на нештатный роутер и не обеспечивает аварийного восстановления.
- Обычный `sysupgrade.bin` нельзя использовать для первой установки через Keenetic.
- Образ Omni II `factory.bin` может не соответствовать реальной WE1626, даже при совпадении модели в экране Keenetic.
- Первоначально открытая сеть означает, что любой человек поблизости может получить доступ к настройкам, пока не установлен пароль.
- После изменения имени или пароля Wi-Fi BALLU и Алиса могут перестать подключаться. Вернуть старые SSID и пароль можно вручную через LuCI.
- Бэкапы `firmware` и `startup-config` не содержат полного образа U-Boot и заводских радиокалибровок.
