# Ballu: локальный сервер на USB-флешке Keenetic и действующая Алиса

Это пакет для NDMS с OPKG на ZBT WE1626 / MT7620, MIPS little-endian,
soft-float, ядро 3.4 или новее. Он не прошивает роутер.

Этот выпуск обеспечивает локальное управление. Он ещё не подключает Алису
к локальному серверу и не решает недоступность HOMMYN при ограничениях сети.
Требования к отдельному прямому каналу описаны в
[ALICE_DIRECT_RU.md](https://github.com/ppmonch2/zbt-we1626-openwrt/blob/main/docs/ALICE_DIRECT_RU.md).

## Схема работы

Локальная страница -> прямой шифрованный Syncleo v3 -> Ballu типа 46.
Удалённые команды Алисы -> уже связанный HOMMYN -> облако производителя -> Ballu.

Алиса обращается к существующему HOMMYN, не к нашему серверу. Оба пути управляют
теми же физическими обогревателями. Без интернета остаётся локальное управление;
штатная удалённая Алиса требует доступности облака HOMMYN с дачи. Никакого обхода ограничений
оператора пакет не обеспечивает. Проброс портов, изменение DNS и перенос устройств
в другой аккаунт не нужны. Имеющуюся привязку HOMMYN к Алисе сохраняем.

## Память

Сервер uhttpd и один небольшой статический C-клиент. Python, Home Assistant и MQTT
не устанавливаются. Файлы и пакеты находятся на USB, не во внутренней флеш-памяти
8 МиБ. Одновременно выполняется одна команда к обогревателю. Реальное потребление
ОЗУ и совместимость старого ядра нужно проверить на конкретном роутере.

## Подготовка флешки

Нужна EXT4 с компонентом EXT в прошивке. Для NDMS до 2.15 раздел должен быть создан
без metadata_csum. Подготовленный раздел должен монтироваться в интерфейсе роутера.
Пакет ничего не форматирует. Если Windows предлагает форматирование EXT4 — отказаться.

1. Распаковать ZIP в отдельную папку на компьютере.
2. Подключить EXT4-флешку к роутеру. Через его сетевой файловый доступ скопировать
   СОДЕРЖИМОЕ папки на корень раздела. Должны получиться:

   /install/mipsel-installer.tar.gz
   /heatbridge-entware/install.sh
   /heatbridge-entware/bin/heatbridge-syncleo
   /README_RU.md

Не распаковывать вложенный mipsel-installer.tar.gz. Это официальный установщик
Entware. Настроенный файловый доступ SMB/FTP нужен для копирования; Windows не
читает EXT4 штатно. Драйвер EXT для Windows устанавливать не требуется.

3. На странице OPKG выбрать этот раздел. Включить доступ к OPKG-сервисам для
   административной учётной записи, если такой флажок присутствует. Применить.
4. В журнале роутера дождаться завершения установки Entware и запуска Dropbear.
   Если установка сообщает об ошибке, не запускать следующие команды, сохранить
   текст ошибки. Обычная установка Entware занимает несколько минут и требует интернета.
5. Подключиться из PowerShell: ssh root@192.168.1.1 -p 222.
   Учётная запись Entware отличается от администратора NDMS. В стандартном
   установщике начальный пароль keenetic; если он был изменён, использовать свой.
   После первого входа сразу выполнить passwd и задать личный пароль.
6. В КОНСОЛИ ENTWARE выполнить:

   sh /opt/heatbridge-entware/install.sh

Если LAN-адрес роутера другой:

   sh /opt/heatbridge-entware/install.sh --lan-ip 192.168.2.1

Установщик проверяет файлы, архитектуру, версию ядра и наличие 64 МиБ свободного
места на USB, ставит пакеты uhttpd_kn, jq, openssl-util. OpenSSL используется для
создания хеша пароля при установке, не для постоянного опроса обогревателей.
Далее попросит НОВЫЙ пароль веб-пользователя heatbridge, минимум 12 символов.
Ввод не отображается. Пароль администратора роутера передавать программе не нужно.

## Первое подключение Ballu

1. Открыть http://192.168.1.1:8765/ (или свой LAN-IP). Пользователь heatbridge,
   пароль тот, который задан установщику.
2. Устройство, телефон/компьютер и роутер должны быть в одной домашней LAN.
   Ballu на Wi-Fi ZTE по другую сторону WISP не обнаружится по mDNS. Для проверки
   перевести один Ballu на домашний Wi-Fi роутера. Гостевую изоляцию не использовать.
3. В HOMMYN: настройки прибора -> Контроль прав -> Поделиться -> скопировать ссылку.
   В локальной странице раскрыть «Подключить обогреватель», вставить полную ссылку.
   Ссылка содержит секретный token: не публиковать её в GitHub или общих чатах.
4. Сохранить привязку, затем «Проверить состояние». До успешного шифрованного
   чтения уставки команды этому прибору заблокированы.
5. После проверки можно задать температуру 5–30 °C, включить «Комфорт» или выключить.
   Проверить изменение на дисплее самого прибора. Точные режимы типа 46 ещё требуют
   испытания на прошивке владельца 1.43.
6. Повторить для остальных устройств. Режимы «Уехал» / «Еду на дачу» задают 12/22 °C
   только проверенным приборам и не включают выключенные.

Свежий адрес, UDP-порт и ключ читаются из mDNS перед каждой операцией. После
перезагрузки прибора старый публичный ключ не используется. Команды после потери
связи сами не повторяются позже. Нет подтверждения — команда могла быть выполнена;
сначала прочитать состояние. Подтверждение протокола не доказывает реальный нагрев.
GET не возвращает токены. Они хранятся только в /opt/etc/heatbridge/config.json,
доступ к файлу ограничен root. Страница локальная HTTP: пользоваться защищённым
домашним Wi-Fi, наружу порт 8765 не публиковать.

## После проверки

1. Проверить управление с локальной страницы при отключённом интернете.
2. Вернуть интернет, проверить существующие команды Алисы.
3. Перезапустить роутер и проверить автозапуск/повторное обнаружение.
4. Если всё работает, подключить модем и флешку одновременно через питаемый USB-хаб.
   Вернуть USB-интернет и отключить ненужный WISP. Флешка остаётся подключённой.

Управление сервером:

/opt/etc/init.d/S80heatbridge status
/opt/etc/init.d/S80heatbridge restart
/opt/etc/init.d/S80heatbridge stop

Остановка сервера не отключает штатный HOMMYN/Алису. Для отключения автозапуска:
chmod -x /opt/etc/init.d/S80heatbridge

Логи веб-сервера: /tmp/heatbridge/httpd.log. Не публиковать config.json, auth-файл,
SSH-пароль и личные ссылки. Пакет не меняет NDMS startup-config и настройки сети.

## Границы проверки

Тесты используют независимую криптографию и UDP-имитатор, а MIPS-файл проверяется
эмулятором QEMU. Это не аппаратные испытания: авторизация, передача состояния,
режимы и автозапуск на конкретном роутере и Ballu требуют проверки владельцем.
Если защищённый handshake проходит без состояния, это не считается рабочим чтением.
